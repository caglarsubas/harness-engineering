# Per-role, per-architecture seccomp allowlists v2 — W02d successor (DATA_CHECK_ONLY)

Status: **SUCCESSOR_CANDIDATE_AWAITING_INDEPENDENT_REVIEW** (reviewed together with the W01 amendment in
`architecture/host-interface-amendment-w02d/`). The adopted W02d contract (`architecture/seccomp-allowlists/`, `planeon.internal.seccomp-allowlists/v1`) stays byte-identical: packet 219's
layer freezes it. This successor is that contract with the changes below, all owner decisions of W01-AMEND
(2026-10-10, via the lane monitor):

| ID | Change |
|---|---|
| W01-AMEND-QW3 (M-a) | The `memfd_create` rule (SERVER, and OBSERVER and BROKER, which inherit it) allows flags `MFD_CLOEXEC \| MFD_NOEXEC_SEAL` (9) instead of `MFD_CLOEXEC \| MFD_ALLOW_SEALING` (3). With `MFD_NOEXEC_SEAL` the kernel clears the exec bits, sets `F_SEAL_EXEC` and still allows further seals (v6.12 `mm/memfd.c:401-410`), and `vm.memfd_noexec` cannot add `MFD_EXEC` (`:313-317`). So every memfd is non-executable without relying on host state; a `vm.memfd_noexec` pin was rejected because a CAP_SYS_ADMIN holder in the initial namespaces can lower it (`kernel/pid_sysctl.h:8-32`, `include/linux/pid_namespace.h:59-67`). The table constant becomes `MFD_CLOEXEC_NOEXEC_SEAL`, the model's policy check requires it, and mutation M09 now tries the v1 flags. |
| W01-AMEND-QW1 | The broker's W6 duty "kill through the pidfd" (`pidfd_send_signal` with signal 9) is dropped: W6 kills through `cgroup.kill` only, and `pidfd_send_signal` to the worker's uid would need CAP_KILL (`kernel/signal.c:814-824`), which the broker does not have. The v2 model refuses any `pidfd_send_signal` grant; the name stays in the table as a sampled refused call. |
| W01-AMEND-QW2 | No allowlist change: W4 never needed `setgroups`; the broker runs with no supplementary groups. The v2 model refuses any `setgroups` grant, and the name is sampled as refused. |

Everything else is the reviewed v1 data, regenerated by the same builder: the syscall numbers and citations, the runtime
bases, every other duty, the compiler and interpreter. `scripts/seccomp_allowlists_v2.py` is the v1 model with only the
memfd check changed and the two refusals above added. The v1 README's rules, runtime bases, digest definition (W02d-Q3)
and stacking (W02d-QD) apply unchanged; its role table and derivation are superseded here only where they list the
memfd flags `MFD_CLOEXEC, MFD_ALLOW_SEALING` and the broker's W6 `pidfd_send_signal` duty. The unused SIGKILL constant
leaves the table. A status record naming v1 as superseded is written after the independent review.

## What changes in the data

- Schemas: `planeon.internal.seccomp-syscall-table/v2`, `planeon.internal.seccomp-allowlists/v2`.
- Filter digests change for BROKER, OBSERVER, SERVER (both architectures) and stay equal for the other roles. Program lengths change only for
  BROKER (one rule fewer).
- Vectors: 2813 decision checks (v1: 2789), 353 worker stack checks (v1: 351), 15 policy mutations (v1: 13; M09 now tries the
  v1 memfd flags, M14 and M15 try to regrant `pidfd_send_signal` and add `setgroups`). Each role with `memfd_create`
  has decision checks killing the v1 flags, `MFD_EXEC` and `MFD_CLOEXEC` alone.

## What stays open

Exactly as v1: no filter is installed, no role code exists, no build is traced, every E01-E12 obligation stays
OPEN_UNPROVEN, and the boot-time proof that installed filters equal these digests stays a T04/W02a-F obligation.
